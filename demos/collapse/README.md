# SUSHI LOOPY — The last piece

42秒の崩壊演出デモ・第3版。ユーザー指定動画のエラー音声を使用し、ダイアログを78件から606件へ増量。終盤は毎秒100件以上が重なり、ブラウザー停止、短いブルースクリーン、完全停止のタメから崩壊へ進む。ゲームの実際の9施設・島・元の76 BPMの旋律を使う。

## 見る

リポジトリのルートで `npm run dev -- --host 127.0.0.1 --port 5196` を実行し、`http://127.0.0.1:5196/demos/collapse/` を開く。「音とともに再生」から開始。シーク、一時停止、音量ON/OFF、全画面に対応。

完成動画: `artifacts/collapse-motion-20261016-windows-storm/sushi-loopy-system-failure.mp4`（1920×1080、30 fps、ステレオ）。比較用の第2版は `artifacts/collapse-motion-20261016-error-cascade/sushi-loopy-system-failure.mp4`、第1版は `artifacts/collapse-motion-20261016/sushi-loopy-the-last-piece.mp4` に残す。

## 実装と検証

`main.js` は既存の `buildTown` と9つのLv.4 GLBを再利用する。頂点を空間セル単位でまとめ、頂点シェーダーで位置と法線を変形し、影にも同じ変形を適用する。時間だけでフレームが決まるため、逆向きのシークも動画書き出しも再現可能。破片は演出用の軌道で、剛体同士の衝突計算はしない。

`score.js` は既存の `notesAtStep` を使ったアレンジと効果音をOfflineAudioContextで構成。エラー音は下記の参照音声をデコードして使用する。新規ライブラリの依存は追加していない。この42秒の試作はゲームの状態やSave Codeへアクセスしない。本編にはエラーウィンドウの描画と音源を共有し、既存の28秒の崩壊に合わせて冒頭10秒へ組み込んだ。共有描画は `src/game/rendering/systemFailure.ts`。文言は本編・デモともシステムエラー調に統一している。書き出し済みの第3版動画は変更前の比較資料として保持する。

`failure.js` のイベント表で序盤の単発音を同期し、共有の `STORM` 時刻で大量発生と参照音声のループを開始する。6種類のウィンドウ画像をキャッシュして、606件を描く際の文字・影の再生成を省く。ダイアログ、カーソル、ブラウザー、ブルースクリーンはすべて映像内の描画で、実際のウィンドウ作成・OS操作は行わない。崩壊本体と余韻は第1版から8秒後ろへ移している。

音源出典: ユーザー指定の [素材- 大量のエラー画面](https://www.youtube.com/watch?v=RtjV0PLqIuo)。`src/game/audio/windows-error-reference.wav` はこの約5.21秒の音声を44.1 kHz・16 bit・ステレオPCMへ変換したもの。音程変更はせず、序盤の単発部分、連続エラー部分、停止時の短い断片を使う。変換前の音声と取得メタデータは `artifacts/collapse-reference-RtjV0PLqIuo/` に保存。エラー音はこの参照動画由来で、Windowsのシステムファイルは変更しない。

```powershell
node demos/collapse/render.mjs
node demos/collapse/render.mjs --webkit
node demos/collapse/render.mjs --render
node demos/collapse/render.mjs --audio
```

検証・書き出しには既存のPlaywrightとFFmpegを使う。Playwrightの場所は `PLAYWRIGHT_MODULE`、URLは `COLLAPSE_URL` で上書き可能。生成物と検証JSONは `artifacts/collapse-motion-20261016-windows-storm/` に保存。各場面の可視性と順序、600件以上の発生と終盤の毎秒100件以上、参照音声の読み込み、タメ中の画素一致と無音、エラー音の音量、実ウィンドウが増えないこと、逆シーク、セーブ無変更、モバイル幅、手動再生、一時停止、ミュートを確認する。WebKitの検証は実機Safari検証とは別。

`--audio` は音だけをWAVへ再出力する。音量ピーク、音楽と破断音の差、直前の無音、終盤の音量も検証する。

停止中の画像は両ブラウザーで完全一致を検証する。逆シークはChromeで完全一致、WebKitでは描画読み戻し時に生じる1階調の差を全チャンネルの0.5%未満まで許容し、実測値を検証JSONに残す。

自動再生は行わない。動きを減らす設定ではカメラ揺れと色収差を除き、利用者が明示的に開始したときだけ映像を動かす。動画そのものは演出のフルモーション版。Windows版Playwright WebKitはWeb Audioを提供しないため、音声非対応を明示して映像を再生する。音付きMP4にはこの制限はない。

# SUSHI LOOPY — The last piece

42秒の崩壊演出デモ・第2版。エラーダイアログと音の増殖、ブラウザー停止、短いブルースクリーン、完全停止のタメを追加。ゲームの実際の9施設・島・元の76 BPMの旋律を使う。

## 見る

リポジトリのルートで `npm run dev -- --host 127.0.0.1 --port 5196` を実行し、`http://127.0.0.1:5196/demos/collapse/` を開く。「音とともに再生」から開始。シーク、一時停止、音量ON/OFF、全画面に対応。

完成動画: `artifacts/collapse-motion-20261016-error-cascade/sushi-loopy-system-failure.mp4`（1920×1080、30 fps、ステレオ）。比較用の第1版は `artifacts/collapse-motion-20261016/sushi-loopy-the-last-piece.mp4` に残す。

## 実装と検証

`main.js` は既存の `buildTown` と9つのLv.4 GLBを再利用する。頂点を空間セル単位でまとめ、頂点シェーダーで位置と法線を変形し、影にも同じ変形を適用する。時間だけでフレームが決まるため、逆向きのシークも動画書き出しも再現可能。破片は演出用の軌道で、剛体同士の衝突計算はしない。

`score.js` は既存の `notesAtStep` を使ったアレンジと効果音をOfflineAudioContextで生成。外部の音源・画像・新規依存は不要。ゲームの状態やSave Codeへはアクセスしない。これは独立した演出試作で、ゲーム本体には組み込んでいない。

`failure.js` の同じイベント表でダイアログとエラー音の発生時刻を決める。ダイアログ、カーソル、ブラウザー、ブルースクリーンはすべて映像内の描画で、実際のウィンドウ作成・OS操作は行わない。崩壊本体と余韻は第1版から8秒後ろへ移し、予備動作の差を比較できるようにした。

```powershell
node demos/collapse/render.mjs
node demos/collapse/render.mjs --webkit
node demos/collapse/render.mjs --render
node demos/collapse/render.mjs --audio
```

検証・書き出しには既存のPlaywrightとFFmpegを使う。Playwrightの場所は `PLAYWRIGHT_MODULE`、URLは `COLLAPSE_URL` で上書き可能。生成物と検証JSONは `artifacts/collapse-motion-20261016-error-cascade/` に保存。各場面の可視性と順序、タメ中の画素一致と無音、エラー音の音量、実ウィンドウが増えないこと、逆シーク、セーブ無変更、モバイル幅、手動再生、一時停止、ミュートを確認する。WebKitの検証は実機Safari検証とは別。

`--audio` は音だけをWAVへ再出力する。音量ピーク、音楽と破断音の差、直前の無音、終盤の音量も検証する。

停止中の画像は両ブラウザーで完全一致を検証する。逆シークはChromeで完全一致、WebKitでは描画読み戻し時に生じる1階調の差を全チャンネルの0.5%未満まで許容し、実測値を検証JSONに残す。

自動再生は行わない。動きを減らす設定ではカメラ揺れと色収差を除き、利用者が明示的に開始したときだけ映像を動かす。動画そのものは演出のフルモーション版。Windows版Playwright WebKitはWeb Audioを提供しないため、音声非対応を明示して映像を再生する。音付きMP4にはこの制限はない。

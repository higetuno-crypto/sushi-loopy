# 最初の寿司屋に承認済みBlenderモデルを適用

施設001（`craftsman`）をLv.1〜4のGLBに置き換えた。既存の`townTier`に従い、職人の所有数1 / 5 / 10 / 25で成長する。所有数0の開店前もLv.1の建物を表示し、職人は購入後に現れる。施設ID、価格、生産、Save v6は変更していない。

## 配置と見た目

- 全レベルを同じ縮尺0.78で配置。カウンターの位置を揃え、Lv.3は右、Lv.4は奥へ増築する。全9区画に移動できる。
- 建物の元の屋根・椅子・寿司の色を維持し、のれんだけ模様替えの色を適用。店名は建物に取り付けた小さな看板へ描く。
- 職人・皿の動きをカウンターの高さに合わせた。店先の猫・ベンチ、配達、写真、動き停止、UI崩壊は継続。

## 配布データ

`public/assets/models/01-craftsman/craftsman-lv{1..4}.glb`

| レベル | tris | マテリアル / 描画メッシュ | GLB bytes |
| --- | ---: | ---: | ---: |
| 1 | 3,520 | 7 | 197,936 |
| 2 | 4,352 | 7 | 241,112 |
| 3 | 5,376 | 7 | 294,460 |
| 4 | 7,006 | 8 | 377,264 |

上記は建物本体。ゲーム内で追加する職人・皿・店名看板は含まない。建物GLBに画像テクスチャはない。材質を分けたのれんが元のモデルより1材質増えているが、形状とtris数は同じ。

原本はローカルの`assets/models/01-craftsman/lvN/craftsman-lvN.blend`。`scripts/export-craftsman-runtime.py`をBlenderで実行すると、原本を変更せずゲーム用GLBを再出力する。編集用Blenderファイルは公開配布しない。

モデルは必要なレベルだけ読み込み、レンダラー内で最大4段階をキャッシュ。新しい段階の読込中は直前の街を維持し、遅れて届いた古い要求は適用しない。失敗は既存の「街を再表示」で再試行できる。描画用の複製とキャッシュの所有権を分け、配置変更や終了時にリソースを解放する。

## 検証

- `npm test`：48件。新しいチェックで4モデルのtris、材質、全9区画の境界、接地、のれん以外の色、キャッシュを破壊しない破棄を確認。
- `npm run lint`、`npm run build`：成功。既存のThree.jsチャンクサイズ警告あり。
- `node scripts/town-check.mjs`：Chrome / Windows WebKit、320×568・390×844・1280×720。実購入で各Lv.の境界を越え、再読込でも段階と色が残ることを確認。Lv.4を離島へ移し、配達が橋を通ることも確認。写真、動き停止、WebGL再作成（Chrome）、UI崩壊も成功。
- 開発版でLv.2応答を遅延させてLv.3を先に表示する競合、Lv.4の通信失敗と再試行、動き停止中のモデル更新、破棄を確認。
- `node scripts/town-journey-check.mjs`：Save Code復元、配達、同期、崩壊、周回、前回の街まで成功。最初の実行では出発待ち8秒を一度超過したが、同じ通し手順の再実行と配達だけの追試では再現しなかった。失敗時の画面・表示時計・可視状態を記録する診断を残した。
- 結果：`artifacts/craftsman-models/`。実機iPhone Safari、発熱・長時間性能は未検証。

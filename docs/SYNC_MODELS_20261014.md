# 009 世界鮮度同期装置 Lv.1〜4

`global_freshness_sync` をBlender製の4段階に置き換えた。金の環、青・白・赤の球体、紺色の観測塔を主役に、25% / 55% / 85% / 120%の成長感を目指した。

## 成長と既存の結末

009は3回目の購入で崩壊に入るため、通常施設の所有数1 / 5 / 10 / 25ではLv.2以降を見られない。既存の購入と同期操作に外見を対応させた。価格、生産量、同期の待ち時間、崩壊条件、セーブ形式は変えていない。

| Lv | 到達する操作 | 主な構成 |
| --- | --- | --- |
| 1 | 1回目の購入 | 小さな観測塔、金の周回レール、3色の球体、琥珀色の核、片側の通信室とアンテナ、寿司の計測台 |
| 2 | 1回目の同期 | 大きい塔と環、反対側の通信室と通信灯、背面の冷却タンク、周回レールの目盛り |
| 3 | 2回目の購入 | 双方のアンテナ、核を囲む立体の環、塔の金の帯、背面デッキ・はしご・塔への連絡通路 |
| 4 | 2回目の同期 | 最大の塔と環、色石の付いた外周環、四隅の灯台、金の玄関庇 |

3回目の購入・崩壊中もLv.4を維持する。写真と「前回育てた街」には、その記録の同期状態を渡して同じ段階を再現する。古い記録で所有数が3以上の場合もLv.4とする。

3色の球体は軸と3本のスポークで支えられたレールと一緒に周回する。アンテナはゆっくり向きを変え、Lv.3の立体環、Lv.4の外周環は異なる速さで回転する。琥珀色と青の信号灯も穏やかに発光する。既存の停止・Reduce Motion・崩壊時の停止に従う。

## 再出力と編集

Blender MCPから次を実行する。`LEVEL` を1〜4に変更できる。

```python
path = 'D:/Sushi_Loopy/scripts/build-sync-models.py'
exec(compile(open(path, encoding='utf-8-sig').read(), path, 'exec'),
     {'__file__': path, 'LEVEL': 1, 'FINAL': True})
```

対象シーンがあれば再利用し、なければ作成する。`FINAL=True` で原本・GLB・4方向画像を保存。土台、塔、通信室、アンテナ、周回レール、核、立体環、デッキを分けて編集できる。基本形状には既存の `scripts/blender_parts.py` を使用する。上位段階は土台と可動軸を流用し、増築と環を追加する。

## 検証

- 4レベル×4方向を確認。背面デッキから塔の入口への連絡通路を補い、Lv.2の増築部には通信灯を付けた。Lv.4にも下位段階の3色の球体を残した。
- 全メッシュで非多様体エッジ・面積ゼロ面・孤立頂点が0。独立した閉じた部品も全て正の符号付き体積（77 / 107 / 139 / 164部品）。各 `checks.json` に記録。
- 置換前に追加テストの失敗を確認。57テスト、lint、型チェックを含むビルドを実行。既存のThree.jsチャンクサイズ警告あり。
- 全9区画で接地と60秒分の可動範囲を検査。実頂点から区画内への収まり、アンテナと周回レール、核と立体環、球体と外周環の隙間を確認。レベルごとのシルエットの拡大、3色の維持、発光、キャッシュ保護も検査する。
- `SUSHI_TEST_FACILITY=global_freshness_sync node scripts/conveyor-check.mjs` で購入・同期による4段階の成長、保存復元、停止、320px幅、模様替え、移動と取り消し、写真を検査。Lv.4では最終購入・崩壊・次の周回・前回の街のLv.4表示まで実際の操作で確認する。`artifacts/sync-models/{chrome,webkit}/` に結果と画像を保存。
- Windows WebKitでは従来と同様、動的な画面サイズ変更後に背景のみになる問題を再現。自動検査の成功だけで全表示が正常だったとは扱わない。実機iPhoneは未検証。
